# StructTrace.Web

**Learn. Visualize. Implement.**

StructTrace.Web is an interactive learning platform for Data Structures and Algorithms (DSA). It combines a structured visual learning experience with a multi-language code workspace, step-by-step trace simulations, and persistent execution history.

The goal is to help learners understand how data structures and algorithms behave—not just memorize their implementations.

> **Project status:** Active development. The application is built with ASP.NET Core MVC and uses Neon PostgreSQL for persistent application data.

## Features

### DSAVisual learning curriculum

The DSAVisual area presents a nine-module Java and pseudocode curriculum covering foundational complexity analysis and core data structures and algorithms. Its learning materials include visualizers, complexity references, pseudocode, and edge-case guidance.

### Interactive Code Sandbox

The Sandbox provides a step-by-step visual workbench for ten topics:

1. Binary Search Tree (BST)
2. Singly Linked List
3. Doubly Linked List
4. Stack
5. Queue
6. Binary Min-Heap
7. Hash Table
8. Breadth-First Search (BFS)
9. Depth-First Search (DFS)
10. Dijkstra's Shortest Path Algorithm

The workbench includes:

- A canvas-based visualization of data structure operations and algorithm trace frames.
- Balanced, worst-case, and randomized input presets where applicable.
- Playback controls to move through trace steps, play or pause a trace, and adjust playback speed.
- Time and space complexity information for the selected topic.
- Language-specific code templates for C++, Java, Python, and C#.
- A code editor with copy and reset-template controls.
- An execution/trace output console.

**Execution note:** The current visual trace is generated by the Sandbox's JavaScript simulation logic. The language selector supplies educational code templates; it should not be interpreted as proof that arbitrary C++, Java, Python, or C# code is compiled and executed by a server-side compiler.

### User accounts and saved traces

- User authentication and authorization are provided through ASP.NET Core Identity.
- Code submissions and saved traces are associated with the signed-in user.
- Saved visual trace data is stored in PostgreSQL using a JSONB column.
- The Sandbox supports saving, loading, and deleting saved trace records.

## Getting started

### Prerequisites

- The .NET SDK version targeted by `StructTrace.Web.csproj`.
- Visual Studio 2022 or another editor that supports ASP.NET Core.
- A PostgreSQL database. A Neon PostgreSQL project can be used for this purpose.
- Git.

### 1. Clone the repository

```bash
git clone https://github.com/Sakhile-shezi/StructTrace.git
cd StructTrace
```

### 2. Restore dependencies

```bash
dotnet restore StructTrace.sln
```

### 3. Configure the database connection

Create or select a Neon PostgreSQL database and copy its connection string from the Neon dashboard.

Configure the connection string using the name expected by `ApplicationDbContext` and `Program.cs`. If the application reads `ConnectionStrings:DefaultConnection`, the environment-variable form is:

```text
ConnectionStrings__DefaultConnection
```

Set its value to your Neon connection string, including the SSL options provided by Neon. Do not paste real credentials into this README or commit them to Git.

For local development, use .NET User Secrets or environment variables rather than storing production credentials in source control. For deployment, configure the connection string in the hosting provider's environment-variable or application-settings panel.

### 4. Apply database migrations

If the repository includes Entity Framework Core migrations, install the EF Core CLI tool if needed and apply the migrations:

```bash
dotnet tool install --global dotnet-ef
dotnet ef database update --project StructTrace.Web --startup-project StructTrace.Web
```

If the EF Core tool is already installed, the installation command can be skipped. Confirm that the migration project and connection-string name match the local project configuration before running the command.

### 5. Run the application

```bash
dotnet run --project StructTrace.Web
```

Open the local URL printed in the terminal. Register or sign in to access the authenticated Sandbox features.

## Database notes

The application data model includes:

- `ApplicationUser` — application users and their related submissions and saved traces.
- `DataStructureLesson` — lesson metadata, complexity information, code templates, and optional vector embeddings.
- `CodeSubmission` — a user's submitted source code and execution notes.
- `SavedTrace` — a user's saved trace title, input sequence, and JSON trace data.

The `SavedTrace.TraceFramesJson` property is intended to map to PostgreSQL `jsonb`. Verify that the EF Core model configuration and the actual Neon schema agree before applying schema changes.

## Security and configuration

Before publishing the repository or deploying the application:

- Never commit database connection strings, passwords, API keys, access tokens, or private certificates.
- Keep production secrets in the hosting provider's secret/environment configuration.
- Review `appsettings*.json`, user-secrets references, GitHub Actions workflows, and deployment files for sensitive values.
- Keep authorization checks on user-specific operations such as loading and deleting saved traces.
- Use HTTPS for the deployed application and a database connection string with SSL enabled.

If a credential has ever been committed to Git, removing it from the latest file is not enough: rotate the credential and review the repository history.

## Deployment

This repository contains an ASP.NET Core MVC application, so it needs a host that can run a .NET server application and provide environment configuration for the Neon database connection.

**GitHub Pages is not a host for this application.** GitHub Pages serves static files and does not run the ASP.NET Core server-side application, authentication, or database endpoints. It can be used for separate static documentation, but not for the full StructTrace.Web application.

A suitable deployment path is:

1. Push the source code to GitHub.
2. Create an ASP.NET Core web application on a hosting service that supports the project's .NET version (for example, Azure App Service).
3. Connect the deployment to this GitHub repository and branch, or configure a GitHub Actions workflow.
4. Add the Neon connection string and other required settings as deployment secrets/environment variables.
5. Apply database migrations using a controlled deployment step.
6. Deploy and test registration, sign-in, DSAVisual, Sandbox trace generation, saving, loading, and deleting.

See the official [Microsoft ASP.NET Core App Service deployment guide](https://learn.microsoft.com/azure/app-service/quickstart-dotnetcore) for an Azure deployment route.
