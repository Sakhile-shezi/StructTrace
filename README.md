# StructTrace

**Learn. Visualize. Implement.**

StructTrace is an interactive Data Structures and Algorithms (DSA) learning platform. It combines visual explanations, step-by-step data-structure and algorithm traces, language-specific code templates, and saved execution history.

## Try StructTrace online

**[Open the live application](https://structtrace-web.onrender.com/)**

Visitors can open the hosted application, register or sign in, explore the DSAVisual curriculum, and use the Code Sandbox.

> **Hosting note:** The live application currently runs on Render's Free web-service tier. Free instances spin down after inactivity, so the first request after a quiet period can take around 50 seconds or longer to respond. This is a hosting limitation, not necessarily an application error.

## Features

### DSAVisual learning curriculum

The DSAVisual area provides a nine-module Java and pseudocode curriculum. It covers foundational complexity analysis and core data structures and algorithms, supported by interactive visualizers, complexity references, pseudocode, and edge-case guidance.

### Interactive Code Sandbox

The Sandbox provides a visual workbench for these topics:

1. Binary Search Tree (BST)
2. Singly Linked List
3. Doubly Linked List
4. Stack
5. Queue
6. Binary Min-Heap
7. Hash Table
8. Breadth-First Search (BFS)
9. Depth-First Search (DFS)
10. Dijkstra's Shortest Path Algorithm

The workbench includes:

- Visual representations of data structures and algorithm trace frames.
- Input sequences and presets for exploring different cases.
- Step controls, play/pause, and playback-speed options.
- Time and space complexity information.
- Code templates for C++, Java, Python, and C#.
- A code editor with copy and reset-template controls.
- An execution and trace output console.

**Execution note:** The current visual traces are generated by the Sandbox's JavaScript simulation logic. The language selector provides educational source-code templates; it should not be interpreted as a server-side compiler that executes arbitrary C++, Java, Python, or C# programs.

### Accounts and saved traces

- Registration and sign-in use ASP.NET Core Identity.
- User-specific submissions and saved traces are associated with the signed-in account.
- Saved trace data is stored in PostgreSQL, with trace-frame data mapped to JSONB.
- Saved runs can be viewed and restored in the Sandbox; deletion is supported by the application.

## Run locally

### Prerequisites

- .NET 10 SDK
- Git
- A PostgreSQL database (Neon can be used)
- An editor such as Visual Studio or Visual Studio Code

### 1. Clone the repository

```bash
git clone https://github.com/Sakhile-shezi/StructTrace.git
cd StructTrace
```

### 2. Restore and build

```bash
dotnet restore StructTrace.sln
dotnet build StructTrace.sln --configuration Release
```

### 3. Configure the database connection

The application reads the connection string named `DefaultConnection`.

For local development, .NET User Secrets can keep credentials out of source control:

```bash
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "YOUR_NEON_CONNECTION_STRING" --project StructTrace.Web/StructTrace.Web.csproj
```

Alternatively, set the environment variable:

```text
ConnectionStrings__DefaultConnection
```

Use the connection string for the Neon branch that contains the application schema. Keep the SSL options supplied by Neon. **Never commit a real connection string, database password, API key, or deployment secret to Git.**

### 4. Apply database migrations

For a database that has not yet been initialized, review the migrations included in the repository and apply them to the intended development database:

```bash
dotnet ef database update --project StructTrace.Web --startup-project StructTrace.Web
```

Do not run migrations against a database containing important data until you have checked the target connection string, reviewed the pending migrations, and made an appropriate backup.

### 5. Run the application

```bash
dotnet run --project StructTrace.Web
```

Open the local URL printed in the terminal.

## Deployment

The live application is hosted on **Render** using the repository's root-level `Dockerfile`.

- Render builds the ASP.NET Core application as a Docker image.
- The container listens on the port supplied by Render.
- Neon PostgreSQL stores application data independently of the container.
- GitHub Actions runs the .NET 10 restore, build, and publish-validation workflow.

The Render service uses environment variables for production configuration:

| Variable | Purpose |
|---|---|
| `ASPNETCORE_ENVIRONMENT` | Set to `Production` |
| `ConnectionStrings__DefaultConnection` | Neon PostgreSQL connection string |

Configure secrets in the hosting provider's environment settings. Do not store production credentials in this repository.

### Render Free tier note

The current public demo uses Render's Free web-service tier. Free services can spin down after inactivity, may have cold-start delays, and are intended for hobby/testing use rather than production workloads. The app's database is hosted separately on Neon.

## Security

- Never commit database passwords, connection strings, API keys, access tokens, private certificates, or publish profiles.
- Store local secrets using .NET User Secrets or environment variables.
- Store deployed secrets in Render's environment settings.
- Use HTTPS and the SSL settings supplied by Neon.
- Review Git history before publishing any credentials. If a credential was committed previously, rotate it; deleting it from the latest version does not remove it from Git history.
