FOUNDATION OF SEARCH

What is Problem Formulation?

Before an AI agent can search for a solution, the problem must be represented in a form that a computer can understand and process.

1.1 From a real-world problem to a search problem

Consider a robot that must move from its current location to a destination. A human might simply say, "Move the robot to the destination." However, a search algorithm requires more precise information.

We need to determine:

  • Where does the robot start?
  • What possible locations can it occupy?
  • Which movements are legal?
  • What happens when a movement is performed?
  • How do we recognise that the destination has been reached?
  • How much does each movement cost?
CORE IDEA

Problem formulation converts an informal problem into a precise model containing states, actions, transitions, a start state, goal conditions and costs.

1.2 What is a state?

A state is a representation of the information about the environment that is necessary to determine what actions are possible and whether the goal has been achieved.

A good state representation contains everything that matters, but avoids unnecessary information. It does not need to record the history of how the agent reached that state.

Example: Two water jugs

Suppose we have a 4-litre jug and a 3-litre jug. The state can be represented as:

(a, b)

Where a is the quantity of water in the 4-litre jug and b is the quantity in the 3-litre jug.

The state (2, 3) means the 4-litre jug contains 2 litres and the 3-litre jug contains 3 litres.

1.3 State versus path

These two terms must not be confused.

State Path
Describes the current configuration. Describes a sequence of states connected by actions.
Does not need to record how the state was reached. Records the route from the initial state.
Example: (2, 3) Example: (0,0) → (4,0) → (1,3) → ...
In the COMP304 guide, states are represented using tuples so that they can be compared, stored in sets and used as dictionary keys. Remember: the state represents the configuration, not the history.
02

FORMAL MODEL

Components of a Search Problem

A search problem must describe the starting configuration, possible states, available actions, resulting states, goal conditions and the cost of a solution.

2.1 State space

The state space is the collection of possible states that can be considered for a problem. Transitions between states are represented by connections or arcs.

2.2 Initial state

The initial state describes the configuration in which the search begins.

For the water-jug problem: (0, 0), because both jugs start empty.

2.3 Actions

Actions describe the operations that an agent is allowed to perform in a state.

For the water-jug problem:

  • Fill the 4-litre jug.
  • Fill the 3-litre jug.
  • Empty the 4-litre jug.
  • Empty the 3-litre jug.
  • Pour water from the 4-litre jug into the 3-litre jug.
  • Pour water from the 3-litre jug into the 4-litre jug.

2.4 Transition model

The transition model specifies the result of applying an action to a state.

TRANSITION NOTATION
Result(state, action) = new state

This notation describes the state produced after an action is applied. It is a supplementary mathematical notation for the transition model.

2.5 Goal test

The goal test determines whether a state satisfies the objective of the problem.

For our water-jug problem, the objective is exactly 2 litres in the 4-litre jug.

GOAL CONDITION
Goal(a, b) = (a = 2)

The amount in the 3-litre jug does not affect the goal condition.

2.6 Action cost and path cost

Each action can have an associated cost. The path cost is the sum of the costs of all actions along a path.

CUMULATIVE PATH COST
g(path) = Σ cost(arcᵢ)

Where each arc represents one transition. The cost of a complete path is the accumulated cost of its transitions.

In the water-jug example, every action costs 1. A solution containing six actions therefore has a path cost of 6.

2.7 Complete problem formulation

Component Water-jug problem
State representation (a, b)
Initial state (0, 0)
Actions Fill, empty and pour.
Transition model Update jug quantities after a legal action.
Goal test a == 2
Action cost 1 for every action.

COMPLETE WORKED EXAMPLE

Trace the Six-Move Solution

The COMP304 Exam Preparation Guide gives the following six-move solution to the water-jug problem. We will calculate each transition carefully.

4.1 Understand the pouring operation

Pouring continues until either the source jug becomes empty or the destination jug becomes full.

AMOUNT TRANSFERRED
t = min(source, destination capacity − destination)

This supplementary formula determines the maximum amount that can be transferred without overflowing the destination jug.

4.2 Initial state

State = (0, 0)

4-litre jug: 0 litres. 3-litre jug: 0 litres. Both are empty.

Goal test: Is a == 2? No, because 0 != 2.

4.3 Step-by-step execution

Step Action Calculation Resulting state
0 Initialise Both jugs empty (0, 0)
1 Fill 4 4-litre jug becomes full (4, 0)
2 Pour 4 into 3 t = min(4, 3 − 0) = 3 (1, 3)
3 Empty 3 3-litre jug becomes empty (1, 0)
4 Pour 4 into 3 t = min(1, 3 − 0) = 1 (0, 1)
5 Fill 4 4-litre jug becomes full (4, 1)
6 Pour 4 into 3 t = min(4, 3 − 1) = 2 (2, 3)

4.4 Detailed calculation of the final pour

Before the final pour, the state is (4, 1).

The 4-litre jug contains 4 litres, while the 3-litre jug contains 1 litre.

Step 1: Calculate the empty space in jug 3.

3 − 1 = 2 litres.

Step 2: Determine how much can be poured.

t = min(4, 2) = 2 litres.

Step 3: Update both jugs.

New jug 4 = 4 − 2 = 2 litres.

New jug 3 = 1 + 2 = 3 litres.

New state = (2, 3).

4.5 Verify the goal condition

GOAL TEST
a == 2

At state (2, 3), the 4-litre jug contains exactly 2 litres. Therefore, the goal test returns True.

4.6 Calculate the total path cost

Every action has cost 1.

g(path) = 1 + 1 + 1 + 1 + 1 + 1

Total path cost = 6.

KEY EXAM LESSON

Always show the resulting state after every action. For pouring operations, show the amount transferred. Do not simply write the final state without demonstrating the calculation.

Choosing a State Representation

5.1 The 8-puzzle

The 8-puzzle contains eight numbered tiles and one empty square. The empty square is represented by 0.

A state is represented as a tuple of nine numbers, read from left to right and top to bottom.

Example state

5.2 Why is a tuple used?

Python tuples are immutable. This means their elements cannot be changed after creation.

A search algorithm often needs to store visited states in a set or use states as dictionary keys. A tuple containing hashable values can be used for these purposes.

When generating a successor, we therefore create a temporary list, change its values, and convert it back into a tuple.

5.3 Towers of Hanoi

The Towers of Hanoi state can be represented using a tuple containing three tuples, one for each peg.

Discs are listed from bottom to top. The first element of each peg tuple is its bottom disc.

Example representation

((3, 2, 1), (), ())

Peg 0 has discs 3, 2 and 1. Peg 1 is empty. Peg 2 is empty.

5.4 State representation rules

  • Include every variable that affects legal actions and goal testing.
  • Do not include information that never changes during the search if it can be stored as fixed problem data.
  • Do not record the path history inside the state.
  • Use a representation that supports comparison and storage.
  • Make sure different configurations have different state representations.
Your examination guide specifically uses the 8-puzzle tuple and Towers of Hanoi nested-tuple representations. Practise explaining why the state must contain the necessary configuration and no unnecessary history.

GENERATING LEGAL STATES

Successor Generation in the 8-Puzzle

A successor is a state that can be reached from the current state by applying one legal action.

6.1 Understand the index calculation

The 8-puzzle is a 3 × 3 grid stored as a one-dimensional tuple. We need to convert the blank's index into a row and column.

ROW AND COLUMN
row, col = divmod(blank, size)

In a grid of width 3, index 4 corresponds to row 1, column 1.

The inverse conversion is: index = row × size + col.

6.2 A worked successor trace

Consider the state supplied in the COMP304 Exam Preparation Guide:

(0, 1, 2, 3, 4, 5, 6, 7, 8)

The blank is at index 0.

row, col = divmod(0, 3) = (0, 0).

We test four possible directions. A movement is legal only if the new row and column are inside the board.

Direction tested New position Legal? Reason
Up (-1, 0) No Row is outside the board.
Down (1, 0) Yes Inside the board.
Left (0, -1) No Column is outside the board.
Right (0, 1) Yes Inside the board.

6.3 Calculate the first successor

The blank swaps with the tile at index 1 × 3 + 0 = 3.

Original:

(0, 1, 2, 3, 4, 5, 6, 7, 8)

Swap index 0 and index 3:

(3, 1, 2, 0, 4, 5, 6, 7, 8)

Action:

slide 3 up

6.4 Calculate the second successor

The blank swaps with the tile at index 0 × 3 + 1 = 1.

Original:

(0, 1, 2, 3, 4, 5, 6, 7, 8)

Swap index 0 and index 1:

(1, 0, 2, 3, 4, 5, 6, 7, 8)

Action:

slide 1 left

COMMON EXAM TRAP

In the guide's code, the action name describes the direction in which the tile moves. This is the opposite of the blank's movement.

6.5 Complete Python successor method

PYTHON 8-PUZZLE NEIGHBORS 
def neighbors(self, node):

    # Find the blank (0)
    blank = node.index(0)

    # Convert index into row and column
    row, col = divmod(blank, self.size)

    result = []

    # Directions describe the tile's movement
    directions = [
        (-1, 0, "down"),
        (1, 0, "up"),
        (0, -1, "right"),
        (0, 1, "left")
    ]

    for dr, dc, name in directions:

        nr = row + dr
        nc = col + dc

        # Check whether the new position is legal
        if 0 <= nr < self.size and 0 <= nc < self.size:

            # Convert row and column into index
            swap = nr * self.size + nc

            # Copy the original immutable tuple
            grid = list(node)

            # Swap blank with the selected tile
            grid[blank], grid[swap] = grid[swap], grid[blank]

            # Create a new immutable state
            new_state = tuple(grid)

            # Record the transition
            result.append(
                Arc(
                    node,
                    new_state,
                    1,
                    action=f"slide {node[swap]} {name}"
                )
            )

    return result

6.6 Why copy to a list and convert back?

  1. node is a tuple and cannot be modified.
  2. list(node) creates a mutable copy.
  3. The two values can now be swapped.
  4. tuple(grid) creates a new immutable state.
  5. The original state remains unchanged.

PYTHON SEARCH FRAMEWORK

Understanding Arc and Path

7.1 What is an Arc?

An Arc represents a transition from one state to another. It contains the starting state, resulting state, transition cost and optionally the action that caused it.

ARC CONSTRUCTOR
Arc(from_node, to_node, cost=1, action=None)
  • from_node: State before the action.
  • to_node: State after the action.
  • cost: Cost of that transition.
  • action: Description of the operation.

According to the COMP304 guide, arc costs default to 1 and must not be negative, because negative costs break lowest-cost-first search.

7.2 What is a Path?

A Path represents a sequence of connected transitions. In the course's Python implementation, paths are linked backwards.

A path is either:

  • A single initial node with no arc.
  • An existing shorter path followed by one additional arc.

7.3 How cumulative path cost works

Suppose we have:

Depot → Market, cost = 1

Market → Station, cost = 3

The path cost is:

0 + 1 + 3 = 4

7.4 Complete Path implementation

PYTHON PATH CLASS 
class Path:

    def __init__(self, initial, arc=None):

        self.initial = initial
        self.arc = arc

        if arc is None:

            # Initial path: no transitions
            self.cost = 0

        else:

            # Accumulate the previous path cost
            # and the new arc cost
            self.cost = initial.cost + arc.cost


    def end(self):

        if self.arc is None:
            return self.initial

        return self.arc.to_node


    def nodes(self):

        current = self

        while current.arc is not None:

            yield current.arc.to_node

            current = current.initial

        yield current.initial

Notice that nodes() yields nodes backwards, beginning with the final node. This is because the Path object stores a reference to its previous path.

7.7 Important debugging question

Consider this incorrect line in the Path constructor: 

self.cost = arc.cost

The problem is that this stores only the cost of the most recent arc. It does not include the cost of the earlier transitions.

Correct:

initial.cost + arc.cost

Incorrect:

arc.cost

This bug affects lowest-cost-first and A*, because both use path cost to order the frontier. Depth-first and breadth-first ignore path cost when selecting paths.

8.3 Complete water-jug problem class

This is the Python formulation from the COMP304 Exam Preparation Guide. It uses the state tuple (a, b).

PYTHON JUGS SEARCH PROBLEM 
class Jugs(Search_problem):

    def start_node(self):
        return (0, 0)


    def is_goal(self, node):
        return node[0] == 2


    def neighbors(self, node):

        a, b = node

        arcs = []

        # Fill the 4-litre jug
        if a < 4:
            arcs.append(
                Arc(node, (4, b), 1, action="fill 4")
            )

        # Fill the 3-litre jug
        if b < 3:
            arcs.append(
                Arc(node, (a, 3), 1, action="fill 3")
            )

        # Empty the 4-litre jug
        if a > 0:
            arcs.append(
                Arc(node, (0, b), 1, action="empty 4")
            )

        # Empty the 3-litre jug
        if b > 0:
            arcs.append(
                Arc(node, (a, 0), 1, action="empty 3")
            )

        # Pour from 4 litres into 3 litres
        t = min(a, 3 - b)

        if t > 0:
            arcs.append(
                Arc(
                    node,
                    (a - t, b + t),
                    1,
                    action="pour 4 into 3"
                )
            )

        # Pour from 3 litres into 4 litres
        t = min(b, 4 - a)

        if t > 0:
            arcs.append(
                Arc(
                    node,
                    (a + t, b - t),
                    1,
                    action="pour 3 into 4"
                )
            )

        return arcs

8.4 Understand the pouring calculations in code

For pouring from jug 4 into jug 3:

t = min(a, 3 − b)

The first argument is how much water is available in jug 4. The second is the remaining capacity of jug 3.

For pouring from jug 3 into jug 4:

t = min(b, 4 − a)

This time, the available water comes from jug 3 and the available space is in jug 4.

8.5 Why do we check whether t is greater than zero?

If t == 0, no water can be transferred. Adding a transition that changes nothing would create a pointless successor.

The condition t > 0 ensures that only meaningful pouring actions are generated.

bool swapped(string grid1stSel, int row1stSel, int col1stSel,
             string grid2ndSel, int row2ndSel, int col2ndSel) {
    bool swappedColours = false;

    if (grid1stSel == grid2ndSel) {                 // both cells in the same grid

            swappedColours = true;
        }
    }
    return swappedColours;
}

                        4) Algorithm that tests whether a state is a goal state [8]

bool isGoalState() {
    for (int i = 0; i < 4; i++) {
        for (int j = 0; j < 4; j++) {
            if (leftGrid[i][j] != rightGrid[i][j]) {
                return false;          // one mismatch is enough
            }
        }
    }
    return true;                       // every cell matched
}

                    


                    

                        5) A heuristic for this problem [5]
                        

                            Count the cells in the left grid whose colour differs from the cell in the same
                            position of the right grid, then divide by 2, the number of cells one valid move swaps:
                        

                        
h(n) = (number of mismatched positions) ÷ 2

                        

                            For the start state there are 9 mismatched positions, so h = 9 ÷ 2 = 4.5.
                            Load the start state above to see the nine numbered cells.
                        

                    


                    

                        6) Is the heuristic admissible? [2]
                        

                            Yes. A valid move swaps two cells in one grid, so it changes the match status of
                            at most two positions. A state with m mismatched positions therefore needs at least
                            m ÷ 2 moves, so h = m ÷ 2 can never overestimate the real number of moves to the goal.
                            Often more than one move is needed per mismatched pair, which makes h an underestimate.
                        

                        

                            A definition of admissibility alone earns no marks; the argument "one move fixes at
                            most two cells" is what the marks are for. Rounding up, ⌈m ÷ 2⌉, is also admissible
                            and slightly more informed.

from searchProblem import Search_problem, Arc

class ColourSwap(Search_problem):
    """State = (left, right); each grid is a tuple of 4 row strings."""

    def __init__(self, left, right):
        self.start = (tuple(left), tuple(right))

    def start_node(self):
        return self.start

    def is_goal(self, node):
        left, right = node
        return left == right                      # cell-for-cell match

    def neighbors(self, node):
        arcs = []
        for g in (0, 1):                          # 0 = left grid, 1 = right grid
            cells = [c for row in node[g] for c in row]
            for a in range(16):
                for b in range(a + 1, 16):
                    if cells[a] != cells[b]:      # same colour = no new state
                        new = cells[:]
                        new[a], new[b] = new[b], new[a]
                        rows = tuple("".join(new[r*4:r*4+4]) for r in range(4))
                        state = (rows, node[1]) if g == 0 else (node[0], rows)
                        arcs.append(Arc(node, state, 1, f"swap {a}<->{b} in {'LR'[g]}"))
        return arcs                               # always 192 arcs

    def heuristic(self, node):
        left, right = node
        m = sum(l != r for lr, rr in zip(left, right) for l, r in zip(lr, rr))
        return m / 2

Eight coins (2024 Q1)9! = 362,8809 circles hold 8 distinct coins and one gap.

                                
Colour swap (Test 1)192 successorsEvery pair of cells in each grid can be swapped (see section 09).

                            
                        

                    


                    
10.3 Worked example: eight coins


                    

                        Successors depend on where the gap is
                        

                            A coin can only move into the empty circle along a line. When the centre is
                            empty, all 8 rim coins can move in, so there are 8 successors.
                            When a rim circle is empty, only its two rim neighbours and the centre coin can
                            move in, so there are 3 successors.
                        

                    


                    

                        A BETTER ADMISSIBLE HEURISTIC
                        

                            h1(n) = number of coins out of place.
                            h2(n) = sum of each coin's clockwise ring distance from its home.
                        

                        

                            Each move shifts one coin by at most one step, so neither heuristic can
                            overestimate. h2 ≥ h1 in every state, so h2
                            dominates h1 and A* with h2 expands fewer nodes.

                        counting questions are marked on the reasoning. Write the formula (9!, C(16, 4),
                        n × 2n) before the number, and say which arrangements you excluded and why.

Question 4 — Debugging


                    

                        A student implements Path using
                        self.cost = arc.cost.
                        Explain the problem and identify which
                        search strategies are affected.
                    


                    

                        Show suggested solution

                        

                            The path cost should accumulate all
                            previous arc costs. Assigning only
                            arc.cost loses the
                            cost of earlier transitions.
                        


                        

                            Lowest-cost-first and A* are affected
                            because they order the frontier
                            using path cost. DFS and BFS do not
                            use path cost when selecting paths.
