SEARCH FUNDAMENTALS

Problem Solving by Graph Searching

A search algorithm explores paths from a starting state until it finds a path that reaches a goal. It does not necessarily explore the entire graph. It expands the graph progressively.

1.1 What information does a search algorithm need?

A generic graph-search algorithm needs:

  • A graph representing the available connections.
  • One or more starting nodes.
  • A goal test that determines whether a node is a goal.
  • A frontier containing paths that are waiting to be explored.

1.2 What is the frontier?

The frontier stores paths that have been generated but have not yet been selected for expansion. Each path starts at the initial node and ends at a node that may lead to a goal.

F
IMPORTANT DEFINITION

The frontier is the collection of paths available for future exploration. The search strategy determines which path is removed from it next.

1.3 The generic search process

  1. Put the initial path into the frontier.
  2. Select and remove one path from the frontier.
  3. Look at the final node of that path.
  4. Test whether that node is a goal.
  5. If it is a goal, return the path.
  6. Otherwise, generate the neighbours of the final node.
  7. Extend the current path with each outgoing arc and add the new paths to the frontier.
  8. Repeat until a goal is found or the frontier becomes empty.
KEY PRINCIPLE FROM THE LECTURE

The search algorithm's control loop can remain the same. The way the frontier selects and returns paths determines the search strategy. This is why changing a stack to a queue or a priority queue changes the behaviour.

02

DATA STRUCTURES

How the Frontier Determines Search

The same graph can produce different search orders because each algorithm chooses its next path differently.

2.1 Depth-First Search — Stack (LIFO)

DFS treats the frontier as a stack. It selects the most recently added path. This causes it to follow one branch deeply before returning to another branch.

STACK RULE
Last In, First Out (LIFO)

The most recently inserted path is the next path removed.

Illustrative frontier

Suppose the stack is: [S→B, S→A], with the top on the right.

DFS removes S→A first. The paths extending S→A are explored before S→B is selected.

2.2 Breadth-First Search — Queue (FIFO)

BFS treats the frontier as a queue. It selects the earliest inserted path. Paths are explored in layers: first the start node, then paths with one edge, then paths with two edges, and so on.

QUEUE RULE
First In, First Out (FIFO)

The oldest path in the queue is removed first.

Illustrative frontier

Suppose the queue is: [S→A, S→B], with the front on the left.

BFS removes S→A first. New paths are added after the paths already waiting in the queue.

2.3 Lowest-Cost-First Search — Priority Queue

Sometimes arcs have different costs. In that case, simply exploring the shallowest path may not find the least expensive solution.

Lowest-Cost-First Search selects the path with the smallest cumulative cost so far. Its frontier is ordered by path cost.

PRIORITY RULE
Select path p with minimum g(p)

Here, g(p) is the total cost of the path from the start node to the endpoint of p.

2.4 The three frontier policies

Strategy Frontier Next path selected Ordering principle
DFS Stack Most recently added Depth first
BFS Queue Earliest added Shallowest paths first
LCFS Priority queue Lowest cumulative cost Cheapest path so far
Memorise the distinction: DFS uses LIFO, BFS uses FIFO, and LCFS uses minimum cumulative path cost. Do not confuse the depth of a path with its cost.

IMPORTANT SEARCH DETAIL

Why is the Goal Tested When a Path is Popped?

The COMP304 search implementation tests the goal after removing a path from the frontier. It does not stop immediately when a goal path is generated.

5.1 Consider this small graph

Arc Cost
S → G10
S → A1
A → G2

5.2 What happens with an early goal test?

When the search expands S, it generates S → G with cost 10. If the algorithm stops immediately at generation time, it returns a solution costing 10.

5.3 What happens with a late goal test?

Lowest-cost-first adds both paths to the frontier:

  • S → A, cost 1
  • S → G, cost 10

It removes S → A first because its cost is lower. It then generates S → A → G, with cost 1 + 2 = 3.

The frontier now contains paths with costs 3 and 10. The path costing 3 is removed first and passes the goal test.

Correct result

Returned path: S → A → G

Cost: 1 + 2 = 3

EXAM RULE

In lowest-cost-first search, a goal path may be generated before the optimal goal path. Testing the goal only when the path is removed from the priority queue avoids returning an unnecessarily expensive path.

ALGORITHM DESIGN

Generic Search Pseudocode

The generic search loop controls the expansion process. The strategy changes how paths are stored and selected.

PSEUDOCODE GENERIC SEARCH 
frontier ← {initial path}

while frontier is not empty:

    path ← select and remove a path

    node ← final node of path

    if goal(node):
        return path

    for each arc from node:

        new_path ← extend path using arc

        add new_path to frontier

return failure

6.1 What changes for DFS?

PSEUDOCODE DEPTH-FIRST SEARCH 
frontier ← stack containing initial path

while stack is not empty:

    path ← pop the top path

    if goal(path.end):
        return path

    for each neighbour in reverse order:

        push extended path onto stack

return failure

6.2 What changes for BFS?

PSEUDOCODE BREADTH-FIRST SEARCH 
frontier ← queue containing initial path

while queue is not empty:

    path ← remove the oldest path

    if goal(path.end):
        return path

    for each neighbour in listed order:

        add extended path to back of queue

return failure

6.3 What changes for LCFS?

PSEUDOCODE LOWEST-COST-FIRST 
frontier ← priority queue containing initial path

while priority queue is not empty:

    path ← remove path with lowest cumulative cost

    if goal(path.end):
        return path

    for each outgoing arc:

        new_path ← extend path

        priority ← new_path.cost

        insert new_path using priority

return failure

6.4 Important Python search methods

The COMP304 guide identifies three frontier operations that a strategy implements:

Method Responsibility
initialize_frontier() Create the required stack, queue or priority queue.
empty_frontier() Determine whether any paths remain.
add_to_frontier(path) Insert a path according to the strategy's priority rule.

The generic search loop repeatedly pops a path, tests its endpoint and generates its successors. The frontier implementation determines which strategy is being used.

PYTHON PROGRAMMING

Implementing the Search Strategies

The following is a self-contained teaching implementation of the course's search framework. It uses the same concepts: Arc, Path, Search_problem, a common search loop and strategy-specific frontiers.

7.1 The Arc class

An Arc represents a connection between two nodes and its cost.

PYTHON ARC 
class Arc:

    def __init__(self, from_node, to_node, cost=1, action=None):

        if cost < 0:
            raise ValueError("Arc costs cannot be negative")

        self.from_node = from_node
        self.to_node = to_node
        self.cost = cost
        self.action = action

7.2 The Path class

A Path stores the previous path and the final arc. Its cost is cumulative.

PYTHON PATH 
class Path:

    def __init__(self, initial, arc=None):

        self.initial = initial
        self.arc = arc

        if arc is None:
            self.cost = 0
        else:
            self.cost = initial.cost + arc.cost


    def end(self):

        if self.arc is None:
            return self.initial

        return self.arc.to_node


    def nodes(self):

        current = self

        while current.arc is not None:

            yield current.arc.to_node

            current = current.initial

        yield current.initial

7.4 The generic Searcher class

The search loop is shared by the three algorithms. Each subclass determines how paths enter and leave the frontier.

PYTHON COMMON SEARCH LOOP 
class Searcher:

    def __init__(self, problem):

        self.problem = problem
        self.num_expanded = 0
        self.max_frontier = 0

        self.initialize_frontier()

        start_path = Path(problem.start_node())

        self.add_to_frontier(start_path)

        self.max_frontier = 1


    def search(self):

        while not self.empty_frontier():

            path = self.pop_frontier()

            self.num_expanded += 1

            # Test the goal when the path is removed
            if self.problem.is_goal(path.end()):
                return path

            # Generate outgoing arcs
            arcs = self.problem.neighbors(path.end())

            # Strategy-specific insertion
            self.add_paths(path, arcs)

            self.max_frontier = max(
                self.max_frontier,
                self.frontier_size()
            )

        return None

7.5 DFS implementation

PYTHON DEPTH-FIRST SEARCH 
class DepthFirstSearcher(Searcher):

    def initialize_frontier(self):
        self.frontier = []


    def empty_frontier(self):
        return len(self.frontier) == 0


    def add_to_frontier(self, path):
        self.frontier.append(path)


    def pop_frontier(self):
        return self.frontier.pop()


    def frontier_size(self):
        return len(self.frontier)


    def add_paths(self, path, arcs):

        # Reverse insertion makes the first neighbour
        # the next path removed from the stack.
        for arc in reversed(arcs):

            new_path = Path(path, arc)

            self.add_to_frontier(new_path)

7.6 BFS implementation

PYTHON BREADTH-FIRST SEARCH 
from collections import deque


class BreadthFirstSearcher(Searcher):

    def initialize_frontier(self):
        self.frontier = deque()


    def empty_frontier(self):
        return len(self.frontier) == 0


    def add_to_frontier(self, path):
        self.frontier.append(path)


    def pop_frontier(self):
        return self.frontier.popleft()


    def frontier_size(self):
        return len(self.frontier)


    def add_paths(self, path, arcs):

        # Add neighbours in their listed order.
        for arc in arcs:

            new_path = Path(path, arc)

            self.add_to_frontier(new_path)

7.7 LCFS implementation

PYTHON LOWEST-COST-FIRST 
import heapq
from itertools import count


class LowestCostSearcher(Searcher):

    def initialize_frontier(self):

        self.frontier = []

        # Counter gives stable ordering for equal costs.
        self.sequence = count()


    def empty_frontier(self):
        return len(self.frontier) == 0


    def add_to_frontier(self, path):

        heapq.heappush(
            self.frontier,
            (
                path.cost,
                next(self.sequence),
                path
            )
        )


    def pop_frontier(self):

        priority, sequence, path = heapq.heappop(
            self.frontier
        )

        return path


    def frontier_size(self):
        return len(self.frontier)


    def add_paths(self, path, arcs):

        for arc in arcs:

            new_path = Path(path, arc)

            self.add_to_frontier(new_path)

PROPERTIES AND COMPARISON

DFS vs BFS vs LCFS

Property DFS BFS LCFS
Frontier Stack Queue Priority queue on g
Next path Last added First added Lowest path cost
Complete? No, can follow a cycle forever Yes, under the guide's assumptions Yes, with non-negative costs
Optimal? No Only if all arcs have equal cost Yes, with non-negative costs
Space behaviour Linear in search depth, in the guide's summary Stores a whole level; main weakness Can require a large frontier

8.1 Why is BFS optimal when all arc costs are equal?

BFS explores paths in increasing order of the number of edges. If every edge has the same cost, a path with fewer edges also has a lower total cost.

Therefore, the first goal path removed from the queue has the minimum number of edges and the minimum path cost.

8.2 Why is BFS not necessarily least-cost?

In a weighted graph, a path containing two expensive edges may cost more than a path containing three inexpensive edges. BFS considers the number of edges, not their weights.

8.3 Why does LCFS find a least-cost path?

LCFS orders paths by cumulative cost. With non-negative arc costs, extending a path cannot reduce its accumulated cost. The first goal path removed from the priority queue therefore has the least path cost.

8.4 Measuring search performance

Your COMP304 guide recommends measuring the number of paths popped (the num_expanded counter) and the largest frontier size.

TWO IMPORTANT MEASURES
Search work = number of paths popped
Space measure = maximum frontier size

Do not compare only execution time. The number of expansions and the maximum frontier show how much search work and stored information were required.

8.5 Supplementary complexity notation

The following are standard tree-search bounds that help explain the space and time trade-offs. They are supplementary to the qualitative comparison in your uploaded lecture slides and guide.

VARIABLES
  • b: branching factor, the average number of successors per node.
  • d: depth of the shallowest goal.
  • m: maximum search depth.
BFS: O(bd+1) time and space
DFS: O(bm) time
DFS: O(bm) space

These bounds assume the standard tree-search model. Repeated-state checking and graph structure can change the practical memory use.

ADDITIONAL LECTURE CONTENT

Bounded DFS and Iterative Deepening

9.1 Bounded Depth-First Search

A bounded depth-first search is given a maximum depth or cost bound. Paths that exceed the bound are not expanded.

This limits how far DFS explores and can prevent it from following an indefinitely deep branch.

Example with depth bound 2

If the start node S is at depth 0, its children are at depth 1 and their children are at depth 2.

A node at depth 2 is not expanded further when the bound is 2.

9.2 Iterative Deepening Search

Iterative deepening repeatedly runs bounded DFS while increasing the depth bound.

ITERATIVE DEEPENING PROCEDURE
  1. Set the depth bound to 0.
  2. Perform bounded DFS with the current bound.
  3. If a solution is found, return it.
  4. Otherwise, increase the bound by 1.
  5. Repeat the bounded search.

9.3 Example sequence of bounds

Iteration Depth bound Search performed
1 0 Only the start node.
2 1 Start and its immediate children.
3 2 Explore up to depth 2.
4 3 Explore up to depth 3.

The lecture asks students to relate iterative deepening to another search method: under the usual finite-branching, unit-depth-cost assumptions, it finds the same shallowest solution as BFS.

LECTURE CONNECTION

Bounded DFS and iterative deepening are included in your Review Search Algorithms slides. They extend the idea of controlling how deep DFS is allowed to explore.

Question 3 — BFS versus path cost

BFS returns S→A→G at a cost of 8. Explain why it does not return S→A→C→G at a cost of 6.

Show suggested answer

BFS prioritises paths with fewer edges, not lower cumulative cost. S→A→G has two edges, while S→A→C→G has three edges. Therefore, the two-edge goal path is removed from the queue first.

Question 4 — Lowest-cost-first

Why is S→B selected before S→A after expanding S?

Show suggested answer

S→B has cost 1, while S→A has cost 2. LCFS selects the path with the smallest cumulative cost.

Question 5 — Debugging the Path class

A student writes: self.cost = arc.cost. Explain why this is wrong and identify the strategies affected.

Show worked answer

The path cost must include all previous arcs. The correct expression is:

self.cost = initial.cost + arc.cost

LCFS and A* are affected because they rely on cumulative path cost to order their frontier.

Question 6 — Changing the insertion method

In the course's DFS implementation, paths are added using: self.frontier.append(path) and removed using pop(). What happens if insertion changes to: self.frontier.insert(0, path), while removal remains pop()?

Show worked answer

The oldest path is now at the end of the list and is removed first. This changes the behaviour to FIFO, which is breadth-first search.

Question 7 — Why reverse neighbours?

Why does the generic search code use reversed(list(neighs)) before adding paths to a stack?

Show worked answer

A stack removes the most recently added path. Reversing the neighbour list before insertion places the first-listed neighbour on top, so DFS follows the neighbour order specified by the problem.

Question 8 — Completeness and optimality

State whether DFS, BFS and LCFS are complete and whether they are optimal, using the assumptions stated in the COMP304 guide.

Show worked answer
  • DFS: not complete in the guide's generic setting because it can follow a cycle forever; not optimal.
  • BFS: complete; optimal only when all arc costs are equal.
  • LCFS: complete and optimal with non-negative arc costs.
