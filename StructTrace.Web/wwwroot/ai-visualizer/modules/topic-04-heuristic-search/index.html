01

INFORMED SEARCH

What is a Heuristic Function?

Uninformed search explores paths using their insertion order or accumulated path cost. Heuristic search uses additional knowledge about the problem to guide the search towards a goal.

1.1 Why do we need heuristics?

Imagine an agent searching for a destination on a map. It could explore every possible route without knowing where the destination is. However, information about the remaining distance can help the search make better decisions.

A heuristic provides an estimate of the remaining cost from the current node to a goal. It helps the search decide which paths appear more promising.

h(n)
DEFINITION

A heuristic function h(n) estimates the cost of reaching a goal state from the current node n.

1.2 The three values used in heuristic search

Symbol Meaning Example
g(n) Actual cost already paid from the start to n. Cost from S to A is 5.
h(n) Estimated remaining cost from n to a goal. Estimated cost from A to G is 3.
f(n) Estimated total cost through n. 5 + 3 = 8.
HEURISTIC OF A PATH
h(p) = h(last(p))

Let p = (n₀, n₁, ..., nₖ) be a path. Its endpoint is nₖ. Therefore, the heuristic of the path is the heuristic of its final node.

ACTUAL PATH COST
g(p) = Σ c(nᵢ₋₁, nᵢ)

The sum is taken over every edge in the path, from the starting node n₀ to the endpoint nₖ. Each c(nᵢ₋₁, nᵢ) is the cost of that edge.

IMPORTANT DISTINCTION

g is the cost already incurred. h is the estimated cost remaining. f combines the two. A* uses all three values to rank paths.

02

HEURISTIC CONSTRUCTION

How Do We Design a Heuristic?

A heuristic estimates how much cost remains to reach the goal. Its formula depends on the problem and the actions that are allowed.

2.1 Straight-line distance

If nodes represent locations and the cost is distance travelled, straight-line distance to the goal can be used as a heuristic.

EUCLIDEAN DISTANCE
d = √((x₂ − x₁)² + (y₂ − y₁)²)

This is the direct geometric distance between two points. It can be a lower bound when the actual route must follow roads or paths that cannot be shorter than the direct distance.

2.2 Time estimation

ESTIMATED TRAVEL TIME
h(n) = distance(n, goal) / maximum speed

This estimates the minimum possible travel time when maximum speed is the upper bound on travel speed.

2.3 Using a simpler version of a problem

A useful heuristic can be obtained by solving a relaxed version of the original problem. A relaxed problem removes some restrictions, making it easier to solve.

The optimal solution cost of that easier problem can be used as an estimate for the original problem.

HEURISTIC DESIGN PRINCIPLE

A heuristic should be informative and efficient to calculate. If an optimality guarantee is required, it must also satisfy the appropriate mathematical conditions.

03

GREEDY PRIORITY

Best-First Search (Greedy)

Best-First Search selects the path whose endpoint has the smallest heuristic value. It chooses the path that appears closest to a goal according to h.

GREEDY BEST-FIRST PRIORITY
Priority(p) = h(last(p))

Select the path whose endpoint has the smallest heuristic value. The accumulated path cost g(p) is not used to determine priority.

3.1 Worked priority example

Path g(path) h(endpoint)
S → A 5 3
S → B 3 2
S → C 2 3

Best-First selects S → B because its heuristic value is 2, the smallest. It does not matter that another path may have a lower cost already paid.

3.2 What does Best-First ignore?

Best-First ignores the cost already incurred when ranking paths. It uses only the estimated remaining cost.

A path may have a small h-value but a very large g-value. Best-First may still select it because it prioritises h only.

3.3 Heuristic Depth-First Search

Heuristic Depth-First Search locally chooses a neighbour that appears closest to a goal according to its heuristic. It then continues with depth-first exploration.

LOCAL HEURISTIC CHOICE
Choose neighbour n with minimum h(n)

This is different from Best-First Search, which selects the globally lowest heuristic value from the entire frontier.

Heuristic DFS Best-First
Chooses a locally promising neighbour. Chooses the globally most promising frontier path.
Uses depth-first exploration. Uses a priority queue ordered by h.
Can follow a poor branch deeply. Can select another path already waiting in the frontier.

3.4 Advantages and disadvantages

Advantages Disadvantages
Uses problem knowledge to guide exploration. Can ignore a large cost already paid.
May find a goal with fewer expansions. Does not guarantee a least-cost solution.
Uses a priority queue ordered by h. Can be misled by a poor heuristic.
04

ACTUAL + ESTIMATED COST

A* Search

A* combines Lowest-Cost-First and Best-First Search. It considers both the cost already paid and the estimated cost remaining.

A* EVALUATION FUNCTION
f(p) = g(p) + h(last(p))

g(p): actual cost of the complete path so far.

h(last(p)): estimated remaining cost from the endpoint of the path to a goal.

f(p): estimated total solution cost through p.

4.1 Calculate an A* priority

Suppose a path to B has cost 3 and the heuristic at B is 2.

g(B) = 3

h(B) = 2

f(B) = 3 + 2 = 5

4.2 Compare the priority rules

Algorithm Priority formula Considers
Lowest-Cost-First g(n) Cost already paid.
Best-First h(n) Estimated remaining cost.
A* g(n) + h(n) Actual cost and estimated remaining cost.

4.3 When does A* test the goal?

A* tests the goal when a path is removed from the priority frontier. It must not stop merely because a goal path has been generated.

IMPORTANT

A different path may still be waiting in the frontier and may lead to a cheaper goal. The priority ordering must be respected before terminating.

OPTIMALITY GUARANTEE

Admissible Heuristics

A heuristic is admissible when it never overestimates the true minimum remaining cost to a goal.

ADMISSIBILITY CONDITION
0 ≤ h(n) ≤ h*(n)

h(n) is the heuristic estimate from node n. h*(n) is the true minimum cost from n to the nearest goal.

An admissible heuristic never overestimates the true minimum remaining cost.

7.1 Worked example

Suppose the true minimum remaining cost from X to the goal is 14.

h(X) True cost Admissible?
1014Yes
1414Yes
1614No — overestimates

7.2 A* optimality conditions

The lecture's stated conditions for A* to find an optimal solution when one exists are:

  1. The branching factor is finite.
  2. Arc costs are bounded above zero.
  3. The heuristic is nonnegative and underestimates the true least cost to a goal.

7.3 Why does admissibility help A*?

When a goal path is removed from the priority frontier, its heuristic value is zero. Its f-value is therefore its actual path cost.

h(goal) = 0
f(goal) = g(goal)

Any unexplored path with a lower possible solution cost would need an f-value smaller than the selected goal's cost. A* would have selected that path first. Admissibility ensures the estimate does not hide a cheaper solution behind an overestimate.

08

HEURISTIC PROPERTY

Consistent Heuristics

Consistency compares the heuristic at one node with the cost of moving to a neighbour and the neighbour's heuristic estimate.

CONSISTENCY CONDITION
h(n) ≤ c(n,n') + h(n')

For every edge from n to n', the estimated cost from n must not exceed the cost of travelling to n' plus the heuristic estimate from n'.

8.1 Worked example: S → B

  • h(S) = 5
  • Cost(S,B) = 3
  • h(B) = 2
5 ≤ 3 + 2

5 ≤ 5 is True.

8.3 Admissible versus consistent

Admissible Consistent
Compares h with the true least remaining cost. Compares h at a node with every outgoing edge and neighbour estimate.
h(n) ≤ h*(n) h(n) ≤ c(n,n') + h(n')
Does not overestimate. Respects the local transition-cost inequality.
EXAM DISTINCTION

Do not prove consistency by checking only the true solution cost. Check every edge using the consistency formula. With nonnegative costs and zero heuristic at goal states, consistency implies admissibility.

9.2 Heuristic 1 — Misplaced tiles

MISPLACED TILES
h₁(n) = number of misplaced numbered tiles

Compare each numbered tile with its goal position. Count a tile when it is not in the correct position. Do not count the blank.

This heuristic is admissible because every misplaced numbered tile must move at least once to reach its goal.

9.3 Heuristic 2 — Manhattan distance

Manhattan distance, also called city-block distance, measures how far a tile is from its goal using horizontal and vertical movements. Diagonal movements are not counted.

HEURISTIC 1 — MISPLACED TILES
h₁(s) = Number of misplaced numbered tiles

Compare the current position of every numbered tile with its goal position. Add one for every tile that is not in the correct position. Do not include the blank tile (0).

HEURISTIC 2 — MANHATTAN DISTANCE
d(t) = |rs(t) − rg(t)| + |cs(t) − cg(t)|
h₂(s) = Σt = 18 d(t)

rₛ(t): current row of tile t. rᵍ(t): goal row of tile t.

cₛ(t): current column of tile t. cᵍ(t): goal column of tile t.

Calculate each numbered tile's horizontal and vertical distance, then add all eight distances. Exclude the blank tile.

9.6 Why is Manhattan distance admissible?

  1. Every numbered tile must reach its correct goal position.
  2. A legal move moves only one numbered tile by one square.
  3. Manhattan distance calculates the minimum horizontal and vertical movements required by each tile, ignoring interference from other tiles.
  4. Therefore, the sum cannot exceed the actual number of moves required.
DO NOT COUNT THE BLANK

The blank tile is not included in misplaced-tile or Manhattan-distance calculations. Counting the blank could overestimate the remaining number of moves.

9.9 Other problems solved using Manhattan distance

Problem How it is used Movement assumption
8-puzzle / 15-puzzle Estimate tile moves to goal positions. Horizontal and vertical.
Grid pathfinding Estimate remaining distance to destination. Up, down, left and right.
Robot navigation Estimate required grid movements. Orthogonal movement.
Warehouse routing Estimate movement between storage cells. Grid aisles.
City-block navigation Estimate distance between street intersections. Street-grid movement.

9.10 When should Manhattan distance not be used?

Manhattan distance assumes horizontal and vertical movement. If the problem allows diagonal moves, the appropriate heuristic may be different.

Movement model Possible distance heuristic
Horizontal and vertical only Manhattan distance
Diagonal moves cost the same as straight moves Chebyshev distance
Diagonal moves cost √2 times a straight move Octile distance
Unrestricted 2D straight-line movement Euclidean distance
Manhattan distance is suitable for the standard 8-puzzle because tiles move horizontally and vertically into the adjacent blank square. It remains a lower bound in grid problems with obstacles when each orthogonal move has unit cost.

PYTHON PROGRAMMING

Implementing Heuristics and A*

10.1 Misplaced tiles heuristic

PYTHON h₁ — MISPLACED TILES 
def misplaced_tiles(self, node):

    misplaced = 0

    for index, tile in enumerate(node):

        # Ignore the blank
        if tile == 0:
            continue

        if tile != self.goal[index]:
            misplaced += 1

    return misplaced

10.2 Manhattan distance heuristic

PYTHON h₂ — MANHATTAN DISTANCE 
def manhattan_distance(self, node):

    total = 0

    for current_index, tile in enumerate(node):

        # Ignore the blank
        if tile == 0:
            continue

        # Current row and column
        current_row, current_col = divmod(
            current_index, self.size
        )

        # Find the tile's goal position
        goal_index = self.goal.index(tile)

        goal_row, goal_col = divmod(
            goal_index, self.size
        )

        # Manhattan distance
        distance = (
            abs(current_row - goal_row)
            +
            abs(current_col - goal_col)
        )

        total += distance

    return total

10.3 A* evaluation function

PYTHON f = g + h 
def a_star_priority(path, problem):

    g = path.cost

    h = problem.heuristic(path.end())

    f = g + h

    return f

10.4 Best-First versus A* priority

PYTHON PRIORITY RULES 
def greedy_priority(path, problem):

    return problem.heuristic(path.end())


def a_star_priority(path, problem):

        problem.heuristic(path.end())

10.5 Complete graph search demonstration

This self-contained Python example demonstrates the priority rules using the graph from the interactive workbench.

PYTHON GREEDY AND A* SEARCH 
import heapq
from itertools import count


GRAPH = {

    "S": [("A", 5), ("B", 3), ("C", 2)],

    "A": [("D", 6)],

    "B": [("D", 7), ("E", 4)],

    "C": [("B", 3), ("F", 8)],

    "D": [],

    "E": [],

    "F": []

}


H = {

    "S": 5,
    "A": 3,
    "B": 2,
    "C": 3,
    "D": 3,
    "E": 0,
    "F": 2

}


def priority(path, strategy):

    nodes, cost = path

    node = nodes[-1]

    h = H[node]

    if strategy == "greedy":
        return h

    if strategy == "astar":
        return cost + h

    raise ValueError("Unknown strategy")


def search(strategy):

    frontier = []

    order = count()

    start_path = (["S"], 0)

    heapq.heappush(
        frontier,
        (
            priority(start_path, strategy),
            tuple(start_path[0]),
            next(order),
            start_path
        )
    )

    paths_popped = 0


    while frontier:

        value, path_name, sequence, path = (
            heapq.heappop(frontier)
        )

        nodes, cost = path

        node = nodes[-1]

        paths_popped += 1


        # Test the goal after popping.
        if node == "E":

            return {
                "path": nodes,
                "cost": cost,
                "paths_popped": paths_popped
            }


        # Generate successors.
        for neighbour, arc_cost in GRAPH[node]:

            new_nodes = nodes + [neighbour]

            new_cost = cost + arc_cost

            new_path = (new_nodes, new_cost)

            new_priority = priority(
                new_path,
                strategy
            )

            # Alphabetical path ordering breaks ties.
            heapq.heappush(
                frontier,
                (
                    new_priority,
                    tuple(new_nodes),
                    next(order),
                    new_path
                )
            )


    return None


greedy_result = search("greedy")

astar_result = search("astar")


print("Best-First:")
print(greedy_result)

print()

print("A*:")
print(astar_result)

BEYOND ONE HEURISTIC

Dominance, Combining Heuristics and Weighted A*

Every search strategy in this course is best-first search with a different evaluation function. Choosing and combining heuristics changes how many nodes A* expands without changing the answer, as long as admissibility is kept.

11.1 One family, five evaluation functions

Strategyf(n)Optimal?
Breadth-firstdepth of nOnly if all step costs are equal
Lowest-cost-first (UCS)g(n)Yes (step costs ≥ ε > 0)
Greedy best-firsth(n)No
A*g(n) + h(n)Yes, if h is admissible (tree search) or consistent (graph search)
Weighted A*g(n) + W × h(n), W > 1No guarantee — it expands fewer nodes but may return a worse path

Weighted A* slides between the others: W = 0 gives lowest-cost-first, W = 1 gives A*, and as W → ∞ it behaves like greedy best-first.

11.2 Dominance

DEFINITION
h2(n) ≥ h1(n) for every n

If both heuristics are admissible and h2 is never smaller, h2 dominates h1, and A* with h2 never expands more nodes. A larger admissible estimate is closer to the true cost.

8-puzzle, solution depth 12Nodes expanded
Iterative deepening (no heuristic)3,644,035
A* with h1 = misplaced tiles227
A* with h2 = Manhattan distance73

11.3 Where admissible heuristics come from

Relaxed problems

Remove a rule and solve the easier problem exactly. Its cost can never exceed the real cost.

8-puzzle: a tile may move anywhere → misplaced tiles. A tile may move to any adjacent square → Manhattan distance.

Take the maximum

h(n) = max(h1(n), …, hm(n)) is admissible when each hi is, and it dominates all of them.

Use it when no single heuristic is best in every state.

Pattern databases

Store the exact cost of solving a subproblem, such as getting tiles 1–4 home while ignoring the others.

Look the value up during search; it is admissible because it solves part of the real problem exactly.
“Why is it admissible?” (2025 Q2.2.2, 2024 Q2.3): name the relaxation, or show that each real move reduces h by at most that move's cost. Example from the Test 1 memo: for the two-grid colour swap, h = mismatched cells ÷ 2 is admissible because one swap fixes at most two mismatched cells.

Local Search: Hill Climbing and Simulated Annealing

Local search keeps only the current state and repeatedly moves to a better neighbour. Use it when the goal state is unknown but every state has a utility u(s): it finds a good state, not a path.

12.1 How it differs from path search

Path search (A*, BFS, …)Local search
GoalKnown goal testUnknown; maximise u(s), s* = argmax u(s)
AnswerA path and its costA single good state; path cost does not matter
MemoryFrontier and search treeOnly the current state(s) — works in huge or continuous spaces

To formulate a local search problem give four things: the state space, a factored state representation, the objective function and the local neighbourhood.

n-QueensTravelling salesman
StateRow of the queen in each column, e.g. (2, 3, 2, 3)A tour (permutation), e.g. ABCED
ObjectiveMinimise attacking pairs (utility = −conflicts)Minimise tour length
NeighbourMove one queen within its columnReverse part of the tour (ABCED → ABDEC)
Space size44 = 256 for 4-queensn! tours

12.2 Hill climbing (greedy local search)

Steepest ascent

Evaluate every neighbour and move to the best one.

Stochastic

Pick at random among the uphill moves.

First choice

Generate random neighbours until one is better, then take it. The most popular variant.

Hill climbing is neither complete nor optimal. It gets stuck on local maxima, on plateaus and shoulders (flat regions) and on ridges. Fixes include random-restart hill climbing (keep the best of many runs), sideways moves and momentum. Maximising f is the same as minimising −f; minimising with derivatives is gradient descent.

12.3 Simulated annealing

METROPOLIS ACCEPTANCE RULE
P(accept a worse move) = e−ΔE / T

Always accept an improving move. Accept a move that is ΔE > 0 worse with probability e−ΔE/T. High T accepts almost anything (exploration); low T behaves like hill climbing (exploitation).

Cooling scheduleFormula
Classic (logarithmic)Tt = T0 / log(1 + t)
ExponentialTt = T0 · αt, with 0.8 < α < 1
FastTt = T0 / (1 + t)

Stop when T < ε. Choose T0 so that even the worst move is likely to be accepted at the start. If T falls slowly enough, annealing finds the global optimum with probability approaching 1 — but usually too slowly to be practical.

Worked calculation from the guide

A move makes the solution 4 worse. At T = 10 it is accepted with probability e−0.4 ≈ 0.67. At T = 1 the same move is accepted with probability e−4 ≈ 0.018.

12.4 Other local methods

  • Local beam search keeps k states and moves to the best k of all their successors.
  • Genetic algorithms are population-based local search (Module 06).
  • Continuous spaces: discretise with a grid of spacing δ; or use gradient descent x ← x − α∇f(x); Newton–Raphson x ← x − H−1(x)∇f(x) uses the Hessian; stochastic gradient descent estimates the gradient from data points and is how neural networks are trained.
  • Convex problems have one optimum and are easy; non-convex problems, like most discrete ones, have many local optima.
