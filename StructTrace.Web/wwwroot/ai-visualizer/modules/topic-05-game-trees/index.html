ADVERSARIAL SEARCH

What are Game-Playing Problems?

In a normal search problem, an agent searches for a sequence of actions that reaches a goal. In adversarial search, another player is actively trying to prevent the agent from achieving its objective.

1.1 Characteristics of the games studied

The Chapter 5 lecture focuses on:

  • Two-player games.
  • Zero-sum games.
  • Deterministic game mechanics.
  • Perfect information, meaning the environment is fully observable.

1.2 The two players

MAX

Maximizer

Tries to obtain the highest possible utility or score.

Chooses the maximum value.
MIN

Minimizer

Tries to obtain the lowest possible utility for Max.

Chooses the minimum value.
0
ZERO-SUM GAME

The players' interests are directly opposed. Min tries to minimize Max's utility while Max tries to maximize it.

1.3 Tic-tac-toe example

Consider a game where X is Max and O is Min. The utility is defined only for terminal states.

Terminal outcome Utility for Max
X wins +1
O wins −1
Draw 0
REMEMBER

All utility values are expressed from Max's perspective. A negative value is bad for Max and good for Min.

1.4 Formal definition of a game

Component Meaning
s₀ Initial state: board, position or hand.
Actions(s) Legal moves available in state s.
Result(s, a) Transition model: state after action a.
Terminal(s) Test that identifies terminal states.
Utility(s) Utility for player Max at a terminal state.
02

STATE-SPACE REPRESENTATION

Understanding Game Trees

A game tree represents the possible sequences of moves from the current state until the game reaches a terminal state.

2.1 How a game tree is organized

  • Each node represents a state or game position.
  • Each edge represents an action leading to another state.
  • MAX and MIN levels alternate.
  • Terminal nodes contain known utility values.
LEVEL 0 MAX

Chooses the largest child value.

↓
LEVEL 1 MIN

Chooses the smallest child value.

↓
LEVEL 2 MAX

Chooses the largest child value.

↓
TERMINAL LEVEL UTILITY

Contains the final scores.

2.2 Game tree versus state space

The lecture uses tic-tac-toe to explain that the same board state can be reached through different sequences of moves. Therefore, a game tree may contain repeated states along different paths.

State space Game tree
Represents reachable states. Represents possible sequences of moves.
A state can be represented once in a graph. The same state can occur in multiple branches.
Connected by state transitions. Organized according to possible plays.

2.3 Why game trees become large

Every possible move can create further possible moves. As depth increases, the tree can become extremely large. This is why the lecture introduces pruning techniques.

03

EXACT GAME-TREE SEARCH

The Minimax Algorithm

Minimax assigns a value to each state. The value represents the result that will be achieved if both players play optimally from that state until the end of the game.

3.1 The decision rule

MAX NODE
MV(s) = max { MV(child) }

MAX selects the largest value among its child states.

MIN NODE
MV(s) = min { MV(child) }

MIN selects the smallest value among its child states.

TERMINAL NODE
MV(s) = Utility(s)

If the state is terminal, its minimax value is its known utility.

3.2 Complete recursive definition

MV(s) =
Utility(s)
if s is terminal
max MV(Result(s,a))
if it is MAX's turn
min MV(Result(s,a))
if it is MIN's turn

The algorithm is recursive. It reaches terminal states, obtains their utility values and then backs those values up towards the root.

3.3 How minimax works

  1. Start at the root of the game tree.
  2. Explore the tree down to terminal states.
  3. Assign each terminal state its utility.
  4. At each MAX node, take the largest child value.
  5. At each MIN node, take the smallest child value.
  6. Continue backing up values until the root is evaluated.
IMPORTANT

Minimax uses depth-first search and evaluates the complete game tree when no depth cut-off is applied. Its optimal decision assumes both players make the best possible moves.

06

REDUCING GAME TREE SEARCH

Alpha-Beta Pruning

Alpha-Beta Pruning improves minimax by avoiding branches that cannot influence the final decision. It returns the same root value as minimax but may examine fewer nodes.

6.1 What are alpha and beta?

ALPHA (α)
α = best value Max can guarantee so far

Alpha is a lower bound on the minimax value available to Max along the current path.

BETA (β)
β = best value Min can guarantee so far

Beta is an upper bound on the minimax value available to Min along the current path.

6.2 Initial values

Variable Initial value Updated by
α −∞ MAX
β +∞ MIN

6.3 Update rules

AT A MAX NODE
α = max(α, v)

MAX updates alpha whenever it finds a better value.

AT A MIN NODE
β = min(β, v)

MIN updates beta whenever it finds a lower value.

6.4 The pruning condition

MOST IMPORTANT CONDITION
α ≥ β

Once alpha becomes greater than or equal to beta, the remaining children of the current node do not need to be evaluated.

6.5 Why can we prune?

Suppose Max already has a guaranteed value of 3 from a previous branch. Max will never choose a different branch that Min can force to a value of 2 or less.

Current alpha = 3.

A MIN node evaluates its first child and gets 2.

Beta becomes 2.

Since 3 ≥ 2, alpha-beta pruning applies.

The remaining children can be skipped.

6.6 Exact pruning rules

Node type Update Prune condition
MAX α = max(α, v) α ≥ β
MIN β = min(β, v) α ≥ β

6.7 Important facts

  • Alpha is updated by MAX.
  • Beta is updated by MIN.
  • Alpha and beta are passed down to child nodes.
  • Node minimax values are returned upwards.
  • Pruning never changes the final root minimax value.
  • The amount of pruning depends on the order in which children are examined.
EXAM WARNING

Do not confuse the values passed down with the minimax values returned upwards. Alpha and beta are bounds; the node's value is backed up to its parent.

07

PYTHON PROGRAMMING

Implementing Minimax and Alpha-Beta

The exam preparation guide represents a game tree using nested Python lists. An integer represents a terminal utility, and a list represents a node with children.

7.1 Minimax in Python

PYTHON MINIMAX ALGORITHM 
def minimax(node, is_max):

    # Terminal node: return its utility value
    if not isinstance(node, list):
        return node

    if is_max:

        best = float("-inf")

        for child in node:

            score = minimax(child, False)

            if score > best:
                best = score

        return best

    else:

        best = float("inf")

        for child in node:

            score = minimax(child, True)

            if score < best:
                best = score

        return best

7.2 Understand the parameters

Parameter Meaning
node The current game-tree node or terminal utility.
is_max True when the current node belongs to MAX; False for MIN.
best Stores the best value found at the current node.
score Value returned by recursively evaluating a child.

7.3 Alpha-Beta Pruning in Python

PYTHON ALPHA-BETA PRUNING 
def minimax_alpha_beta(node, alpha, beta, is_max):

    # Terminal node
    if not isinstance(node, list):
        return node

    if is_max:

        best = float("-inf")

        for child in node:

            score = minimax_alpha_beta(
                child, alpha, beta, False
            )

            best = max(best, score)

            alpha = max(alpha, best)

            # Prune the remaining children
            if alpha >= beta:
                break

        return best

    else:

        best = float("inf")

        for child in node:

            score = minimax_alpha_beta(
                child, alpha, beta, True
            )

            best = min(best, score)

            beta = min(beta, best)

            # Prune the remaining children
            if alpha >= beta:
                break

        return best

7.4 Starting the algorithm

PYTHON INITIAL CALL 
tree = [[5, 3, 9], [2, 8, 7], [6, 1, 4]]

result = minimax_alpha_beta(
    tree,
    float("-inf"),
    float("inf"),
    True
)

print(result)

The initial player is MAX, so the final argument is True. Alpha starts at negative infinity and beta at positive infinity.

7.5 Finding the best move at the root

PYTHON BEST MOVE 
def best_move(tree):

    best_index = None

    best_score = float("-inf")

    for i in range(len(tree)):

        score = minimax(tree[i], False)

        if score > best_score:

            best_score = score

            best_index = i

    return best_index

This function assumes that the root is MAX and that its direct children are MIN nodes. It returns the index of the child MAX should choose.

7.6 Common programming mistakes

Mistake 1 — Wrong initial value at MIN 
# Incorrect
best = float("-inf")

# Correct
best = float("inf")

MIN searches for a smaller value, so its initial value must be positive infinity.

Mistake 2 — Not alternating players 
# Incorrect
score = minimax(child, is_max)

# Correct
score = minimax(child, not is_max)

Every level switches between MAX and MIN.

Mistake 3 — Updating the wrong bound 
# MAX node
alpha = max(alpha, best)

# MIN node
beta = min(beta, best)

MAX updates alpha and MIN updates beta. Both players use the same pruning condition: alpha ≥ beta.

08

ALGORITHM ANALYSIS

Minimax and Alpha-Beta Complexity

The game-tree branching factor and maximum depth determine how many nodes may need to be evaluated.

SEARCH TREE PARAMETERS
b = maximum branching factor
m = maximum search depth

8.1 Minimax complexity

Measure Complexity Reason
Time O(bm) Minimax explores the complete game tree.
Space O(bm) Depth-first search stores the current path and unexplored siblings.

8.2 Why pruning is useful

Alpha-Beta Pruning can reduce the number of nodes that must be evaluated. The exact savings depend on the order in which children are examined.

MOVE ORDERING

Alpha-Beta prunes more effectively when promising moves are examined earlier. Reordering can change the number of leaves visited, but it does not change the minimax root value.

8.3 Exam points

  • Minimax traverses the game tree using depth-first search.
  • Alpha-Beta avoids evaluating branches that cannot alter the decision.
  • The root value remains the same with and without pruning.
  • Pruning efficiency depends on move ordering.

CHAPTER 5 EXTENSIONS

Beyond Complete Minimax Search

The Chapter 5 slides also discuss what happens when the complete game tree is too large or when random events influence the game. These are additional lecture concepts beyond the core Minimax and Alpha-Beta skills highlighted in the exam guide.

9.1 Heuristic Alpha-Beta Tree Search

Instead of searching all the way to terminal states, the algorithm can stop at a chosen depth and use a heuristic evaluation function.

CUTOFF EVALUATION
Eval(s) ≈ estimated utility of state s

The evaluation estimates how promising a non-terminal state is.

The lecture specifies that the evaluation function should be:

  • Fast to compute.
  • Within the utility range of a loss to a win.
  • Correlated with the actual chance of winning.

9.2 Linear evaluation function

WEIGHTED FEATURES
Eval(s) = Σ wᵢfᵢ(s)

Each fᵢ(s) represents a feature of the current game state, and each wᵢ is the weight assigned to it. The lecture gives pieces captured in chess as an example of a feature.

9.3 Forward pruning

Forward pruning ignores moves that appear poor according to a heuristic. The lecture lists possible ways to estimate move quality:

  • Low heuristic value.
  • Low evaluation value after a shallow search.
  • Past experience.
RISK OF FORWARD PRUNING

A move that appears poor may actually be important. Forward pruning can therefore discard a move that would have led to a better decision.

9.4 Monte Carlo Tree Search (MCTS)

Monte Carlo methods estimate the value of a game state by simulating complete games, also called playouts, and averaging the resulting utilities.

AVERAGE PLAYOUT UTILITY
Estimated utility = Total utility / Number of playouts

The lecture describes four main ideas associated with MCTS:

  1. Selection of a node in the existing partial tree.
  2. Expansion of the selected node.
  3. Simulation of a game to a terminal state.
  4. Back-propagation of the outcome through the selected path.

9.5 Exploration and exploitation

Exploration Exploitation
Try states or moves that have received few simulations. Use more simulations on moves that have performed well.
Discover potentially better alternatives. Improve confidence in promising choices.

9.6 UCB1 selection formula

UPPER CONFIDENCE BOUND
UCB1(n) =
U(n) / N(n) + C √(log N(parent(n)) / N(n))

U(n) is the total utility of playouts through node n. N(n) is the number of those playouts. N(parent(n)) is the parent's playout count. C is the exploration constant.

The first term represents exploitation. The second term encourages exploration. The lecture gives approximately 2 as a typical value for C.

9.7 Stochastic games and Expectiminimax

Some games contain random events such as dice rolls or dealt cards. These games require chance nodes in addition to MAX and MIN nodes.

CHANCE NODE EXPECTED VALUE
Value(s) = Σ P(r) × Value(Result(s,r))

Each possible random outcome r is weighted by its probability P(r). The resulting expected values are combined.

Question 4 — Debugging Minimax

A student's MIN branch starts best = float("-inf"). The function returns negative infinity. Identify the error and correct it.

Show suggested answer

MIN tries to find the smallest child value. It must start with the largest possible initial value: 

best = float("inf")

Starting at negative infinity means no ordinary child value will be smaller, so best is never updated.

Question 6 — Why does order matter?

Reordering children can change how many leaves Alpha-Beta evaluates. Does this change the answer?

Show suggested answer

No. Alpha-Beta pruning never changes the root minimax value. The order matters because better early values create tighter alpha and beta bounds, allowing more branches to be pruned.
